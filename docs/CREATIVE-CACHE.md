## Producer activity boundary

`AppActivity.check(producers:)` returns `running`, `notObservedRunning`, or `unknown`. It reads current-user kernel process identity and executable-path metadata under the no-materialization policy. It does not read project contents, arguments, environment, or preferences, and does not close applications. Unsupported producers, incomplete observations, malformed buffers, and detected process churn yield unknown activity.

Compiled names cover selected Photoshop, After Effects, render-engine, Lightroom Classic, Media Encoder, and Resolve identities. Bridge has no independently verified executable identity: the trusted metadata lookup was refused by ownership checks, while an application inventory label alone does not verify its executable or helpers. The candidate's declared producer set therefore yields `unknown`. Executable and bundle-family matching is conservative but incomplete; independently renamed helpers outside recognized bundles can escape it.

For a rule with `requiresClosedApplications: true`, the scanner checks activity before and after each path job and discards that job's findings if either observation is running or unknown. Findings retain the required producer set. Grouping and removal reject a mismatch against the current rule, including an attempt to remove the requirement. Removal repeats activity checks before staging, capture, and Trash. These are observations, not locks: another process can launch or exec after a check. Existing [removal and recovery limits](REMOVAL.md) still apply.

## Grouping and attribution

`CreativeCacheGrouping.group` consumes a completed report, its rule set, reviewed mappings, and optional caller-supplied project resolutions. It performs no filesystem lookup or path-based project inference. A mapping must retain every rule producer. Application-wide groups remain separate from project caches with unknown attribution; absent or ambiguous association evidence stays unknown.

An explicit project association retains its supplied provenance per finding. It is not a claim that RACKET discovered or verified vendor metadata. Group identity combines the full producer set declared by the rule with a stable project ID; matching project titles do not merge identities. Paths and opaque project IDs use exact UTF-8 identity, including when Swift considers two Unicode spellings equivalent. Retaining all declared producers does not establish that the provisional vendor catalogue is complete.

Groups preserve the original findings, internal observations, producer requirements, risk, reasons, and regeneration costs. They reject duplicate or inconsistent inputs, version mismatches, invalid timestamps, and size overflow. Totals report observed allocated bytes. `lastTouched` is the latest finding modification time, not a verified project-open or application-activity timestamp. Mixed-risk and judgement groups cannot become preselectable through attribution; grouping never grants removal permission.
